# 0.2.0 更新：退款与资产归属

- 默认按分类自动冲减退款，未关联原消费也能抵扣；分类不明确可稍后批量整理，跨月退款记在退款发生月。原始凭据保留。

- 基金页面显示买入减赎回的净投入，不表示实时市值或投资收益；存款余额仍需要期初与完整流水。
- 账本结构升级到版本 2，读取旧账本无需重新导入。请退出旧版再打开新版；新版本保存后的账本应使用 0.2.0 或以上版本。

# 青禾账本

本地个人财务管理系统框架。React / TypeScript / Vite + Tauri 2 / Rust / SQLite。

六个页面：财务总览、交易流水、我的账户、导入中心、分析报表、设置与备份。默认进入独立的虚构演示空间，桌面版左下角切换个人账本。

## 开发与构建

需要 Node.js 22+。Windows 桌面还需要 Rust stable（MSVC 目标）、Visual Studio C++ Build Tools / Windows SDK、WebView2 Runtime。参考 [Tauri Windows prerequisites](https://v2.tauri.app/start/prerequisites/#windows)。

```powershell
npm.cmd install
npm.cmd run dev             # 浏览器演示，http://127.0.0.1:1420
npm.cmd run desktop         # 本地桌面应用
npm.cmd test
npm.cmd run build
cd src-tauri
cargo test -p qinghe-core
```

安装包：在项目根目录执行 `npm.cmd run desktop:build`，输出到 `src-tauri/target/release/bundle/nsis/`。WebView2 使用离线安装器打包。前端不使用远程字体、图像、CDN 或在线服务；开发依赖下载及打包时的 WebView2 组件下载需要网络。

## 数据与边界

- 桌面数据：`%LOCALAPPDATA%\PersonalFinance\personal\ledger.db`；演示为相邻 `demo` 目录。数据库、原始账单、备份未加密，由系统用户账户保护。
- 浏览器只开放演示，使用独立 IndexedDB；个人账本、SQLite、桌面备份恢复需运行 Tauri。浏览器演示备份 JSON 不作为桌面备份使用。
- SQLite 分表保存账户、原始行、标准交易、导入批次、关系、分类规则和元数据。原始文件以 BLOB 保存在 `originals`，与流水原子提交；备份快照包含原始文件，无需依赖源文件路径。
- 所有写入使用 SQLite `BEGIN IMMEDIATE` 事务和 revision 检查；桌面金额解析、导入校验、关联校验、批次撤销在 Rust 端执行。前端统计使用纯函数，Rust 提供同口径 `query_totals`。
- 备份 `.qinghe` 是带 SHA-256 清单的 ZIP，包含 SQLite Online Backup API 生成的快照。恢复校验空间、版本、摘要、数据库完整性及业务引用；先在当前空间的 `backups` 目录备份当前状态，再原子恢复。
- 仅人民币，金额以整数分存储。已确认重复仅计算主记录；本人转账不计收支；退款按退款日期自动冲减支出，分类不明确的可稍后整理。凭据关联可选；关联时累计退款不能超过原消费。手续费须作为单独支出行。
- 账户余额必须同时有期初余额和用户确认流水完整；否则显示期间净变动。导入或撤销后，账户完整性会重置为待核对。
- 未确认跨平台候选可能使统计重复；顶部铃铛与总览提示进入核对，单渠道不再仅凭金额与时间提示重复。流水表保留所有原始凭据，汇总剔除已确认重复；流水明细 CSV 导出同样保留凭据。

## 通用导入

支持首行唯一表头的 `.csv` / `.xlsx`（第一张工作表），上限 20 MB / 50,000 行。CSV 支持 UTF-8 及 GBK，XLSX 支持日期单元格。使用导入中心的模板最容易开始。

必填映射：交易时间、金额（元）、收支类型。可选：商户、平台流水号、备注。类型支持 `收入 / 支出 / 退款 / 转入 / 转出 / 转账收入 / 转账支出 / 充值 / 提现`。金额最多两位小数，日期 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm:ss`，无时区日期按 UTC+8 展示。金额正负号不决定资金方向，方向由类型列确定。

同文件在相同账户和渠道内拦截；可靠流水号在相同账户和渠道内去重。无流水号的相同金额、时间只给建议，不自动删除。任何错误行都会阻止整批提交；修正原文件后重新选择。

支付渠道与资金账户需分清：微信刷银行卡时，渠道选微信、账户选银行卡。多资金来源混合账单请先拆分成同一资金账户的表格再导入。支付宝交易明细已支持说明区、GBK/GB18030 编码、混合换行符、第 24 行表头、末尾空列及长订单号。微信和银行原始格式仍待样本适配。暂不支持 PDF、截图或 API。

## 验证

`npm.cmd test` 覆盖金额精度、非法日期、可靠单号去重、无单号保留、原始记录不变、跨平台关联撤销、转账、退款上限与日期、批次撤销。`cargo test` 覆盖 Rust 解析、关联、CSV 校验、事务回滚与 SQLite 快照。

UI 手动验收：六页导航；月份切换；隐藏金额；图表跳转；流水搜索与批量分类；交易抽屉；关联及撤销；账户编辑；通用导入预览与提交；批次撤销；备份恢复；125% / 150% 缩放。

支付宝固定格式已按用户提供的 2026 年导出样本适配；微信和银行专用格式待样本提供后接入。

## 支付宝导入规则

- 自动寻找完整的 12 个标准列，无需手动删除前置说明；文件仍需从系统解压为 CSV 后选择。
- 失败或纯取消记录不进入标准交易，原始行和完整原文件保留；有可核验全额成功退款的已关闭原消费保留入账，与退款相抵。成功的零元交易有效，正常保留。
- 按原始收支标记区分收入、支出；投资理财、本金还款等“不计收支”保留为独立类型，不推断资金方向。投资退款同样不冲减生活支出。
- 消费退款直接按分类冲减支出；退款订单号能唯一确定原消费时自动继承分类，原单关联仅用于凭据核对。
- 长订单号全程作为文本。去重同时区分账户、渠道、订单号、交易类型、资金方向和原始事件分类，避免投资购买与退款共用订单号时丢行。
- 按付款方式分配资金来源，可选择现有账户或自动建立来源账户。“花呗&红包”等组合保留原文，归组不代表已拆分实际扣款。
- 支付宝金额用于收支分析；因优惠、组合支付、花呗、投资等不能准确还原资产变化，来源账单不直接用于计算账户余额。界面显示“期间记账净额”，不作为资产或负债余额。
- 未知状态直接报告源文件行号并阻止提交，避免未来格式变化被静默忽略。

本地只读核验（不会导入数据，也不会输出姓名、流水号或金额）：

```powershell
node scripts/validate-alipay.mjs '<本地支付宝CSV路径>'
```

仓库只包含虚构示例 `examples/支付宝格式演示.csv`，不包含用户原始账单。

## 本机便携编译工具

当前项目的 `.tools` 中准备了便携 Rust / LLVM-MinGW，不修改系统 PATH；仅在启动脚本的进程中设置环境。

```powershell
./scripts/desktop-portable.ps1 -Task Test
./scripts/desktop-portable.ps1 -Task Dev
./scripts/desktop-portable.ps1 -Task Build
```

便携 Build 生成带嵌入前端资源的调试版桌面可执行文件，便于先体验框架；正式分发仍建议使用标准 MSVC 工具链构建安装包。`.tools` 与 `target` 均不进入版本控制。
